# 吃啥呢 V2 前端原型

这是与旧 Demo 隔离的 V2 首页原型。V2.5 已加入高德地图 JS API 加载与定位，不包含真实餐厅接口或后端服务。

## V2.5 地图与定位

V2.5 已接入高德地图 JS API 2.0、浏览器定位和模拟餐厅真实坐标 Marker。餐厅内容仍为模拟数据，不连接任何真实餐厅接口。

4家模拟餐厅在 `data/restaurants.js` 中保留固定测试经纬度和 `isMock: true` 标记。定位成功后，前端会把整组测试坐标平移到用户当前位置附近，只生成运行时坐标，不修改源数据，并保持餐厅之间的方向和距离差异。

先在 `map-config.js` 中填写高德开放平台申请的 Web 端（JS API）Key 和 `securityJsCode`。该文件中的真实密钥不应提交到公开仓库；当前无后端方案只用于本地开发验证。

## 运行

不要直接双击 HTML。请进入 `v2` 目录，通过本地 HTTP 服务运行：

```powershell
python -m http.server 8080
```

然后访问 `http://localhost:8080/`。浏览器会在地图加载完成后请求位置权限。图片使用公开的远程样例图片链接，因此离线时图片区域可能无法显示。

## 文件

- `index.html`：首页语义结构，包括顶部搜索、真实地图容器、餐厅列表、用户菜单、决定按钮和小助手入口。
- `styles.css`：移动端 App 布局与暖色视觉；负责地图/列表 50:50、70:30 和 30:70 三种状态。
- `data/restaurants.js`：原型使用的模拟餐厅数据与模拟地图坐标。
- `map-config.js`：本地高德 Web Key 与安全密钥配置。
- `map.js`：封装高德地图加载、地图实例、定位、餐厅 Marker、信息卡、选中状态、尺寸刷新和错误处理。
- `app.js`：负责搜索过滤、地图比例切换、定位状态、模拟坐标运行时适配、动态展示距离、用户菜单及“帮我决定一家”的演示逻辑。

## 当前边界

- 地图使用高德 JS API 2.0，显示用户位置和4家模拟餐厅 Marker。
- 餐厅 `location` 是围绕参考中心的测试坐标；定位后会整体平移到用户附近。
- 页面展示距离根据用户位置和运行时餐厅坐标动态计算；原有固定 `distance` 不会被覆盖，继续供当前推荐原型使用。
- 未配置高德 Key 时，地图区域会显示明确的配置提示。
- 餐厅均为模拟数据。
- “帮我决定一家”会在收集人数、场景和预算后允许提前推荐；完整路径再补充尝试程度、关怀条件和距离限制，并展示匹配比例与未满足条件。
- “帮我决定一家”会打开独立的饭饭陪伴式条件决策层，通过人数、场景、预算、尝试程度和关怀条件完成本地规则匹配。
- 预算使用整顿饭的预计总价；家庭默认按 4 人、多人聚餐默认按 6 人估算，自定义人数按实际输入估算。
- 推荐结果始终提供“就吃这家”“换一家”和“重新选择”，关闭流程后会回到原地图首页。
- 自然语言规则解析移入首页右下角的“小饭饭助手”；辅助输入支持文字和语音交互占位，确认后可直接推荐，修改时会带着已识别条件进入主条件流程。
- 小饭饭助手提供“饭饭帮我选一个”“懒得选？告诉饭饭”和“看看怎么玩”三个入口。快速帮选只在当前基础候选中轮换，不展示评分或算法，并避免连续出现同一家。
- 助手默认是首页下半部分内的轻量悬浮工具。展开时仅隐藏底部主按钮，不刷新列表、不改变地图比例、滚动位置或选中餐厅；关闭后恢复原状态。
- 列表支持在“距离优先”和“人均优先”之间切换，餐厅卡片右上角可以收藏；收藏数据保存在当前浏览器的 `localStorage` 中。
- 页面初次加载只初始化地图，不自动请求定位；用户点击定位按钮后才申请位置权限。位置只在当前页面内用于计算附近距离，不写入本站 `localStorage`。
- 发布到公开站点前，应在高德控制台把 Web Key 限制到实际站点域名，并单独管理安全密钥；公开仓库中的前端配置对所有人可见。
- 新手引导首次访问时自动展示一次，之后可从助手主动重新打开；首次状态仅保存在当前浏览器的 `localStorage` 中。
- 用户菜单和小助手只展示原型反馈，不包含完整子页面。

## 地图列表联动测试

1. 允许浏览器位置权限，确认用户附近出现4个暖橙色 Marker。
2. 点击餐厅列表卡片，确认地图移动到对应位置、Marker 高亮并显示信息卡。
3. 点击地图 Marker，确认对应列表卡片进入选中状态。
4. 检查列表距离随定位动态变化，并显示为 `320m` 或 `1.2km` 等格式。
5. 拒绝定位时，真实地图仍保留，但不创建模拟餐厅 Marker。

未来接入真实餐厅接口时，只需在数据适配层把接口 POI 转换为当前 Restaurant 模型，并直接使用真实 `location.lng/lat`；删除测试坐标平移步骤即可，地图 Marker 和列表联动无需重写。
